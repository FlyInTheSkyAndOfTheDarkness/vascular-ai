# Деплой VascularAI на сервер

Оба сайта и PostgreSQL запускаются на одном сервере из `compose.yaml`.

| Адрес | Сервис |
| --- | --- |
| `https://med-it.asia` | Статический лендинг |
| `https://cabinet.med-it.asia` | Вход, кабинет врача, администратора и все рабочие разделы |

PostgreSQL не публикует порт в интернете. Кабинет доступен через Caddy; тот
обслуживает HTTPS и WebSocket. База, вложения и сертификаты находятся в постоянных
томах Docker. Таблицы `users`, `patients`, `visits`, `attachments`, `activity`
и новые столбцы создаются автоматически перед запуском кабинета. Модель уже
включена в репозиторий; повторное обучение для деплоя не требуется.

## Первый запуск

На Linux-сервере должны быть Docker Engine с Compose v2.24.4+ и Python 3.
Проверьте: `docker compose version` и `python3 --version`.

1. Направьте DNS A-записи `med-it.asia` и `cabinet.med-it.asia` на IP сервера.
   Если опубликованы AAAA-записи, IPv6 также должен вести на этот сервер.
2. Разрешите входящие TCP 80/443 в сетевом экране сервера и хостинга.
   UDP 443 нужен только для HTTP/3. Освободите эти порты от другого веб-сервера
   либо интегрируйте правила из `deploy/Caddyfile` в существующий прокси.
3. Загрузите проект на сервер и выполните из его корневой папки:

```bash
python3 tools/setup_server.py
docker compose up -d --build
docker compose ps
```

`setup_server.py` один раз создаёт `.env` с отдельными случайными паролями БД,
администратора и ключом сессий. Повторный запуск не меняет существующие секреты.
Файл исключён из Git и Docker-образа. При переносе исходников не копируйте `.env`
с тестового компьютера: создайте новый на сервере.
Рабочие CSV локального компьютера также не включаются в образ: первый запуск
создаёт новую серверную базу, а не импортирует эти файлы автоматически.

Первый вход: логин `admin`, пароль — значение `ADMIN_PASSWORD` в серверном `.env`.
Откройте файл локально на сервере; не публикуйте его и не отправляйте в чат.
В админ-панели создайте аккаунты врачей. После первичного создания администратора
пароли меняются в кабинете: изменение `.env` не сбрасывает пароль существующего
пользователя и пароль уже созданной базы PostgreSQL.

Caddy запрашивает сертификаты после того, как DNS и порты доступны извне.
Схема выдачи сертификатов: [Caddy automatic HTTPS](https://caddyserver.com/docs/automatic-https).
Поддержка WebSocket: [Caddy reverse_proxy](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy).

## Проверка после запуска

```bash
docker compose ps
docker compose logs --tail=80 cabinet web
curl -fsS https://cabinet.med-it.asia/_stcore/health
```

Проверьте в браузере лендинг, переход «Войти», вход администратора и врача,
создание тестовой карты, три разных расчёта, историю, отчёт и вложение.
Изменение показателей убирает старый результат; после «Рассчитать риск» в блоке
«Показатели, использованные в расчёте» видны фактически принятые значения.

Проверка контейнера включает доступность Streamlit, подключение к PostgreSQL и
схему таблиц. Успешный HTTP health сам по себе не заменяет проверку входа и расчёта.
Если база недоступна, приложение сообщает об ошибке и не переключается на CSV.

## Обновление

Перед обновлением сделайте резервную копию. Затем загрузите новые исходники,
сохранив серверный `.env`, и выполните:

```bash
docker compose up -d --build
docker compose ps
```

Данные в томах сохраняются при пересборке и перезапуске. Команда
`docker compose down -v` удаляет тома: её нельзя использовать для обычного обновления.
Добавление столбцов выполняется автоматически и сохраняет старые строки.
Если обнаружены повторяющиеся ID в старой БД, создание уникального индекса
останавливается: сначала нужно разобрать дубликаты, а не удалять данные.

## Резервная копия

```bash
python3 tools/backup_server.py
```

Скрипт ненадолго останавливает кабинет, сохраняет согласованные `database.dump`
и `attachments.tar.gz`, затем запускает кабинет снова. Полная копия помечается
файлом `COMPLETE` в `backups/<дата-в-UTC>/`. Скопируйте эту папку и отдельно `.env`
на другое защищённое хранилище. Копия на том же сервере не защищает от потери сервера.

Для восстановления в новый пустой серверный стек:

```bash
docker compose build cabinet
docker compose up -d db
docker compose exec -T db pg_restore -U vascularai -d vascularai --no-owner --exit-on-error < backups/DATE/database.dump
docker compose run --rm --no-deps -T cabinet tar -xzf - -C /app/data/clinic < backups/DATE/attachments.tar.gz
docker compose up -d
```

Замените `DATE` на папку копии. Эти команды предназначены для пустой базы;
восстановление поверх существующей БД требует отдельного плана, чтобы не смешать данные.

## Локальная проверка серверного стека

```bash
python3 tools/setup_server.py
docker compose -p vascularai-validation -f compose.yaml -f deploy/compose.local.yaml up -d --build
```

Лендинг: `http://med-it.localhost:18080`.
Кабинет: `http://cabinet.med-it.localhost:18080`.
Используются отдельные тома с префиксом `vascularai-validation`, без публичного HTTPS.
Локальный тест публикует PostgreSQL только на `127.0.0.1:55438`; серверный стек
порт БД не публикует. В `deploy/wheels/` можно хранить полный проверенный набор
Linux wheels для сборки без сети; без них Docker устанавливает зависимости с PyPI.
Если браузер или ОС не разрешают поддомены `.localhost`, добавьте оба имени в hosts
с адресом `127.0.0.1` только для этой локальной проверки.

## Границы модели

Это прототип общего материнского риска, не модель вероятности преэклампсии.
В расчёт входят только возраст, верхнее и нижнее давление, глюкоза, температура
в градусах Фаренгейта и пульс. ИМТ, срок, биомаркеры и анамнез сохраняются
в истории визита и не влияют на прогноз. Локальная проверка без пересечения
профилей дала среднюю accuracy 66,43%; независимая клиническая проверка не проведена.
