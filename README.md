# VascularAI

Streamlit-приложение для кабинета врача и оценки maternal health risk.

Внутри проекта теперь есть два слоя:

- `app.py` - рабочий кабинет врача: пациентки, визиты, прогноз риска, SHAP-факторы, дашборд и вложения.
- `static/landing/` - локальный клон лендинга из `https://github.com/Xsteel212109/vascular-ai`, включая CSS/JS, логотип, favicon и 3D-ассеты.

## Возможности кабинета

- Создание карты пациентки (возраст, срок, ИМТ, анамнез, врач).
- Прикрепление визита к пациентке.
- Расчёт риска по 6 показателям: возраст, давление, сахар, температура, пульс.
- Сохранение результата модели, вероятностей, главного SHAP-фактора, а также ИМТ, биомаркеров (PLGF, PAPP-A, SFLT-1, MAP) и отметок анамнеза.
- Прикрепление файлов к карте пациентки: CSV, XLSX, PDF, PNG/JPG, TXT.
- Вход в кабинет, роли `Врач` / `Администратор`.
- Окно входа — один статичный экран без прокрутки: слева лого, 3D-модель и сменяющиеся подсказки о платформе, справа — форма входа.
- Админ-панель отделена от кабинета врача: вкладки `Управление доступом`, `Аналитика врачей`, `Журнал действий`.
- Аналитика врачей: объём расчётов, распределение риска, динамика по неделям и карточка-разбор по каждому врачу.
- Журнал действий: входы и выходы, расчёты, создание карт и аккаунтов, вложения, смена доступов и паролей - с фильтрами по периоду, действию и пользователю, выгрузка в CSV.
- Сессия входа сохраняется на 14 дней на текущем устройстве; кнопка `Выйти` завершает её.

3D-модель плода показывается только в окне входа; внутри кабинета врача её нет.

## Разделы кабинета врача

Структура повторяет макет Medical AI Platform Design:

- **Дашборд** - приветствие с датой и отделением, 4 KPI-карточки (расчёты за месяц, высокий и средний риск, последний расчёт), кнопка нового расчёта и таблица последних пациенток.
- **Новый расчёт** - пошаговая форма с секциями «Антропометрия и витальные показатели», «Биомаркеры (при наличии)», «Анамнез»; результат и SHAP-факторы справа.
- **Пациенты** - поиск по ID, фильтры-чипы (риск, срок, период), таблица с действиями «История» и «Новый расчёт», постраничная навигация.
- **История пациента** - карточка пациентки со статистикой, график динамики риска по неделям, история расчётов и вложения.
- **Отчёты** - период, выгрузка в CSV и печатная сводка, KPI, кольцевая диаграмма распределения риска и столбчатая динамика по неделям.
- **Настройки** - профиль врача (имя, фамилия, email, телефон, клиника, специальность), смена пароля, уведомления и язык интерфейса.

Общие элементы: сайдбар с иконками и профилем (прижат к низу), верхняя панель с кликабельными хлебными крошками, быстрым поиском пациента, уведомлениями и меню профиля. KPI-карточки дашборда кликабельны и ведут в соответствующие разделы.

## Запуск

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python src\train_model.py
python -m streamlit run app.py
```

После запуска откройте адрес, который покажет Streamlit, обычно:

```powershell
http://localhost:8501
```

Если порт занят:

## Серверный деплой

Целевая схема: `med-it.asia` — лендинг, `cabinet.med-it.asia` — все кабинеты.
Весь стек разворачивается на вашем сервере: Caddy + Streamlit + PostgreSQL.
Таблицы создаются и обновляются автоматически; база и вложения остаются в
постоянных Docker-томах после перезапуска.

```bash
python3 tools/setup_server.py
docker compose up -d --build
```

До запуска направьте DNS обоих доменов на сервер и откройте порты 80/443.
Первый логин — `admin`, пароль создаётся в серверном `.env` (ADMIN_PASSWORD).
Полная инструкция, проверка, обновление и резервные копии:
[docs/deployment.md](docs/deployment.md).

GitHub Pages оставлен как ручной альтернативный workflow; основной деплой — на сервер.
Внешние SaaS-сервисы и ручное создание таблиц не требуются.

## Локальные данные и проверка

Без DATABASE_URL локальное приложение использует CSV в `data/clinic/` и
`data/auth/`; этот режим предназначен для разработки. Если DATABASE_URL задан,
ошибка подключения останавливает операцию, а не переключает её на CSV.
В production (`APP_ENV=production`) обязательно постоянное хранилище.

Локальный лендинг: `python -m http.server 8000 --bind 127.0.0.1 --directory static/landing`.
Кабинет: `python -m streamlit run app.py`. Кнопка входа с localhost открывает порт 8501.

```powershell
python -m unittest discover -s tests -v
node --test tests/cabinet-link.test.cjs
python tools/validate_model.py
```

В ограниченной Windows-среде Node можно запускать с
`node --preserve-symlinks-main --preserve-symlinks --test tests/cabinet-link.test.cjs`.

Тесты используют временные хранилища. Проверяют миграцию, конфликты записи,
вход, роли, расчёты, историю, вложения, вероятности, SHAP и переходы между доменами.
Интеграционные тесты БД могут работать с PostgreSQL через TEST_DATABASE_URL;
они создают и удаляют только свои временные схемы с префиксом `va_test_`.

## Качество модели

Модель оценивает три класса общего материнского риска из Maternal Health Risk.
ИМТ, срок, биомаркеры и анамнез сохраняются для истории и не входят в расчёт.
Встроенные метрики исходного разбиения (81,28% accuracy) оптимистичны из-за
совпадающих профилей в обучении и тесте. На пяти разбиениях без пересечения
профилей средняя accuracy — 66,43%, диапазон — 58–75%.
Это внутренняя проверка, а не клиническая валидация или прогноз преэклампсии.

Модель включена в `models/`; обучение вручную: `python src/train_model.py`.
Перед добавлением данных: `python src/audit_dataset.py --input PATH --name NAME`.
Отчёты аудита: `reports/dataset_audits/`; локальной проверки: `reports/local_validation/`.
